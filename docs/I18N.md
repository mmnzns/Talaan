# Languages (English, French, Spanish)

Talaan's screens come in English, Canadian French and neutral Spanish. Settings › General › Language picks one;
Auto follows the system language and falls back to English. It does not change the meeting or summary language.

## How it works

- `src/lib/i18n/messages/<area>.ts`: one file per part of the UI (`onboarding`, `settings`, `meeting`, `shell`,
  `recording`, `kit`, `platform`, `common`). Each exports `area({ en, fr, es })`; the compiler requires the same keys in
  all three. Register a new area in `src/lib/i18n/index.ts`.
- Components: `const t = useT();` then `t("settings.someKey", { name })`. Outside React: `import { t } from "lib/i18n"`.
- Placeholders are `{name}`. Plurals are `key_one` / `key_other` with `{count}`.
- Keys built at run time (model ids): `messageOr(lang, "settings.model_note_" + id, fallback)`.
- Windows/Mac words (settings app name, menu bar vs system tray) are in `messages/platform.ts`, read with `usePlatform()`.
- Dates follow the language (`lib/format.ts`: en-US, fr-CA, es-US).
- Me / Them are translated for display only (`speakerName`); the stored values stay `me` / `them:0` / "Me".
- Windows-only screens (the calendar's iCal address, the "ready" browser state, the Privacy calendar line) use their
  own keys (`settings.ics_*`, `settings.browser_desc_windows`, `onboarding.calendarLater`, …); pick them with `onWindows`
  from `lib/platform.ts`.
- Rust strings (tray menu and tooltip, "Summary ready", recorder notices, the Windows calendar's address errors, Notion
  headings, and every error or refusal the app shows: updates, Ask, summaries and the summary AI services, Notion,
  import, model downloads, secure key storage, the recorder) are in `src-tauri/src/i18n.rs`, read with `tr` / `tr_with`,
  or `tr_err` when a technical detail goes in `{error}`. The frontend reports the resolved language through
  `i18n_set_language`.
- Rust uses the language it was given last: until the window has loaded and called `i18n_set_language`, it's English
  (for example the tray menu built at launch, or an error raised before the first screen shows).
- Reasons stored in meeting.json are English. When the screen has its own text for a code it shows that instead
  (`no_model`, and the summary codes `waiting`, `too_short`, `no_engine`: `summaryErrorText` in `src/data/errors.ts`).

## Rules (same as Parlato)

1. Every sentence exists in all three languages.
2. Proper accents always; Spanish opens questions and exclamations with ¿ and ¡; sí/si, tú/tu, más/mas by meaning.
3. Platform-neutral wording; brand names stay untranslated; model notes show in the app language.
4. Code comments, ids and internal errors stay as they are.
5. `src/lib/i18n/i18n.test.ts` checks keys, placeholders, accents and ¿/¡ mechanically. Run it after any translation.

## Stays in English

- Technical details inside a translated message (`{error}`, `{detail}`): operating system errors, HTTP client errors,
  what an AI service or Notion says about a failed request, and the local AI helper's own error text.
- Errors that only a bug could cause (an unknown provider or model id) and internal sentinels (`cancelled`).
- Speech engine and audio device failures (loading a model, a microphone format the app doesn't support, system audio
  capture), which show inside "Transcription failed: …" or a recorder warning.
- Text stored in meeting.json (a failed meeting's reason, placeholder titles such as "Call, Zoom, …" and
  "Imported: …"), shown as stored unless the screen has its own text for the code (above).
- Dates inside Ask answers' meeting references ("Oct 14"), the model names, the dev-only Screens stage and sample
  data.
